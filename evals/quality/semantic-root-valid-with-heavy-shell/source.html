Reliable batch processing for nightly reports

Batch processing is reliable when each job records its input, output, and retry state.

This guide describes the worker boundary, the retry policy, and the metrics needed to diagnose a failed run.

Worker boundary

The worker reads one immutable job description and writes one result record before acknowledging the queue.

Retry policy

Transient failures use bounded exponential backoff. Permanent failures are retained for manual review.

Metrics

Track duration, retry count, output rows, and the age of the oldest pending job.
