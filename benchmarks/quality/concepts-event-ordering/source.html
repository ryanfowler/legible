Event ordering model

Ordering is guaranteed only within one partition. Events from different partitions can arrive in any relative order.

A partition is an ordered append-only sequence. The broker assigns an offset after it accepts an event, and consumers read offsets in increasing order. This guarantee does not imply that wall-clock times increase or that two producers observe one shared sequence.

Select a partition key from the entity whose state must remain consistent. An account identifier is suitable when all account changes must be applied in order. A random key distributes load well but gives consumers no useful ordering boundary.

Producer sequence

Each producer writes a monotonic sequence number into the event envelope.

The sequence protects against a producer retry that reaches the broker after a later write. The consumer stores the last accepted value for each entity. It can ignore an older duplicate and can pause processing when it observes a gap that requires recovery.

A producer must keep its sequence state in durable storage. Resetting the number after a process restart makes a valid new event look like a duplicate. If durable state is not practical, use an epoch identifier with the sequence and define how consumers adopt a new epoch.

Consumer responsibility

Consumers must handle duplicate delivery because a retry can occur after the broker stores an event.

Apply an event and record its offset in one transaction when the data store supports that operation. Otherwise, make the update idempotent and record a stable event identifier. Acknowledging before either record is durable can lose work after a crash.

Consumers that combine partitions need an explicit merge rule. They can process events as they arrive, wait for bounded timestamps, or calculate a derived view independently for each partition. No choice creates a global order that the broker did not provide.

Next steps

Record the last applied sequence per entity, test replay from an older offset, and alert on gaps before accepting production traffic.
